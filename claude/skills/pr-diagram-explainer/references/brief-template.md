# 作図をサブエージェントに任せるときの指示書

サブエージェントは会話の文脈を持たない。図の問い、正本、用語、出力先を指示書だけで渡す。
`<...>` を埋め、要らない行は消す。

```markdown
PR 本文に貼る解説図を <N> 枚作ってください。対象の変更は「<変更の 1 文要約>」です。
作り方は <skill-dir>/SKILL.md の 2〜5 節と <skill-dir>/references/style.md に従います（先に読む）。
図は HTML/CSS で組み、`figtool.py new --like <型>` で例から始め、`figtool.py render` で PNG にします。

## 正本
- <設計書の絶対パス> を全文読み、用語と数値をこれに合わせる。実装は <ファイルの絶対パス>。
- 用語: 「<語>」（<定義>）。「<使わない語>」は使わない。
- repo の git には触らない（読むだけ）。

## 1 枚目 `<name>.html`: <図が答える問い>
- 型: <layers / before-after / steps / 流れの列 / 判定の表 / 反映順序 / データの形>
- 主張: <見出しにする 1 文>
- 見せるもの: <箱、矢印、×、結論のラベル。実例の識別子や値もここで決める>

## 出力
<作業用ディレクトリの絶対パス> に HTML と PNG（`.png` と `.gh.png`）を置く。
`figtool.py check` の ERROR を 0 件にし、`.gh.png` を Read で見て、5 秒で主張が分かるか、重なりやはみ出しが無いかを確かめる。
最終報告はパスと、各図に載せた要素の 1 行要約だけにする。
```

親は戻ってきた図に対して自分で `check` を流し、`.gh.png` を見て、ラベルを正本と突き合わせてから添付する。
直させるときは、どの図のどの要素をどう変えるかを具体的に書いて同じサブエージェントに送る。
