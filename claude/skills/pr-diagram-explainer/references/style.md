# 体裁の詳細

SKILL.md の「見せ方を決める」「組む」の補足。部品は `assets/base.css`、矢印は `assets/wires.js`、組み方の実物は `assets/examples/` にある。

## 目次

- 寸法と文字
- 色
- 部品
- 図の型ごとの組み方

## 寸法と文字

- 図の幅は 1000px で固定する（`.fig`）。`render` はこれを 2 倍の 2000px の PNG にし、GitHub は幅およそ 880px で表示する。
- 文字は 15px 以上にする。880px に縮めて 13px になり、これより小さいと読めない。本文は 17px、補足は 15px、見出しは 30px が基準である。
- 高さは内容なりでよいが、縦に長すぎる図（高さが幅の 1.4 倍超）は本文で一度に見えない。そうなったら図を分ける。
- 箱と箱の間は 30〜50px あける。矢印のラベルや × を置く所は、それが収まる幅をあける。

## 色

役割を 2 つに分ける。1 枚の中で同じ色に両方の役割を持たせない。

**カテゴリ色**（層、主体、repo、段の区別）: `.c-amber`、`.c-slate`、`.c-blue`、`.c-violet`、`.c-pink`。
帯（`.lane`）やカード（`.card`）の薄い塗りと、同じ系統の濃い文字で使う。
凡例は帯の名前そのものか、`.legend` の点にする。

**意味の色**（状態）: 赤 `.c-red` = 失敗、違反、拒否、悪化。緑 `.c-green` = 成功、通る、改善。灰色 = 対象外、届かない、未実施。
状態は色だけで伝えず、`.verdict` や `.pill` の語、`.icon` の ✓ / ✕、× の印を添える。

- グラデーション、影、片側だけの色の太線、絵文字、イラスト、漫画風の装飾は使わない。強調は塗り、全周の枠、太字、大きさで表す。
- 見出しは黒の極太（800）、補足は灰色の細字にし、強弱の差をはっきり付ける。

## 部品

base.css のクラス。組み合わせ方は examples を見る。

|部品|クラス|使い所|
|---|---|---|
|見出し|`.eyebrow`、`.title`、`.subtitle`|上から、所属（任意）、答えを言い切る見出し、前提を 1 行|
|凡例|`.legend` と `.dot` / `.swatch`|色や線種に意味があるとき。右上か見出しの下|
|帯|`.lane`（`.label` と `.body`）|層、レーン。左に名前、右に箱|
|カード|`.card`（`.head`、`.heading`）|段、パネル、まとまり|
|箱|`.node`（`.name`、`.sub.mono`）|名前と実例の識別子。`.changed` はこの PR、`.muted` は届かない、`.dashed` は仮のもの|
|結論|`.verdict`、`.result` と `.icon.ok` / `.icon.ng`|失敗 / 成功、引き受けられる / 引き受けられない|
|ラベル|`.pill`、`.badge`、`.tag`|状態（要判定、直した）、「この PR」、変更前 / 変更後|
|数|`.big`|件数を見せたいとき。`<small>` で単位|
|補足|`.detail`、`.note`、`.caption`|文はここだけ。`.note` は左に太字のラベル、`.caption` は図の下|
|番号の説明|`.key`|違反の矢印の番号と、その説明、関係する名前|

矢印は `wires.js` が描く（書式は冒頭のコメント）。

- 既定は直角に折れる線（`elbow`）。束ねたい矢印や、斜めに長く走る矢印は `curve` にする。
- 同じ辺から複数出す、同じ辺へ複数入るときは `at` / `to_at` でずらす。
- 箱を迂回させたいときは、出る辺と入る辺を同じ向きにし（右から右など）、`offset` で外側を回す。
- ラベルは短い動詞（「読む」「書く」）。線が短くてラベルが箱にかぶるなら、ラベルを行き先の箱の中の `.pill` にする。

## 図の型ごとの組み方

### 層と参照の向き（examples/layers.html）

- 層を上から下へ帯で並べ、各帯に実例の箱を置く。主な流れは同じ列に縦に揃える。
- 許す参照は実線の矢印、違反の例は赤の破線に × と番号。番号の説明は図の下の `.key` に、違反を検出する仕組みの名前と並べる。
- 「矢印の無い参照は全て違反」のような規則の要約は `.caption` に 1 行。

### 変更前と変更後（examples/before-after.html）

- 同じ配置のパネルを左右に並べ、`.tag` で「変更前」「変更後」を付け、パネルの見出しに結論を 1 行で書く。
- 違いは、灰色にした箱、短い破線と ×、緑の枠と緑の矢印だけで見せる。
- 届く先の権限などは、行き先の箱の中の `.pill` にする。

### 段と結果の分岐（examples/steps.html）

- 段を ①〜④ のカードで左から右に並べ、間に `→` を置く。カードの高さは揃える。
- 各段の下に、その段で起きうる結果を小さな箱で並べる（赤 = 失敗、灰色 = 何もしない、黄 = 格下げ、緑 = 通る）。
- 最後の段（ゴール）だけカードを緑にすると、どこまで通れば成功かが分かる。

### 流れの列

- 段を ①〜④ の大きなカードにし、カテゴリ色で塗り分けて、間に `→` を置く。
- 各カードの中は、見出し、その段の中身の実例（小さな表、上位の項目、`.big` の件数）、`.detail` の 1〜2 行。
- 段をまたぐ定期の処理などは、図の下の `.note` に書く。

### 判定の表

- 行に状況、列に変更前 / 変更後を置く表にする（表でよいのは、セルを見比べることが目的のとき）。
- 各セルは、色付きの `.verdict`（失敗 / 成功）と短い理由を先に、`.detail` の根拠を後に置く。結論が先に目に入るようにする。

### 反映順序

- PR や作業を箱にし、並行できるもの、前提になるもの、後片付けを列に分けて左から右へ並べる。
- repo や担当で箱の色を分け、この PR だけ塗りつぶす。凡例は図の下に。
- 順序を誤ると壊れる所は赤の × で示し、理由は本文へ。

### データの形

- 入力の数行と出力の数行を小さな表で並べ、行の対応を矢印でつなぐ。
- 主キー（grain）の列を太字にし、増える行、消える行、NULL になるセルを色と点線で示す。
- 行は 3〜5 行に絞り、その変更の論点が現れる行だけを選ぶ。
