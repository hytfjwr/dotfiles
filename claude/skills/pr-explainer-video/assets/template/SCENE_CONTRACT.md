## 1. 担当とファイル

- 1 シーン＝ `parts/sNN.py` の 1 ファイル。**自分の担当の `sNN.py` だけを作る・直す**
- 共通のファイル（`style.css`、`engine.js`、`scenes_base.py`、`tts.py`、`build.py`、`render.js`、`stills.js`、`video.json`、`readings.json`、`assets/`）は直さない。足りない部品や読みは lead に依頼する。共通のファイルを変えると全シーンのハッシュが変わり、撮り直しになる
- **読みの直しは `readings.json` に足すよう lead に頼む**（`tts.py` は直さない）。そのシーンだけの読みは `scene(readings=[(表記, 読み)])`
- シーン固有の見た目は `scene(css=...)` に書く（セレクタは `#sNN` で始める）
- 素材は `assets/`（スクリーンショットは `assets/<...>/`、録画クリップは `assets/clips/<name>.mp4` と同名の `.json`）。無い図は HTML と CSS で描く（`card` `chip` `bubble` `harrow` など）

## 2. コマンド

```bash
cd <作業ディレクトリ>
python3 build.py 3 --kana        # 読みの確認（音声エンジンが解釈したアクセント句を出す）。読みの罠は §7
python3 build.py 3 --stills      # 各ステップの中ほどと終わりの静止画 → stills/s03_<k>_mid.png / _end.png
python3 build.py 3               # 動画を撮る → seg/v03.mp4（中身が前回と同じなら撮らない）
node <スキルの scripts/clipcheck.js> . 3   # 見切れ・重なりの検査（§8）
```

- 番号を付けずに `python3 build.py` を実行しない（全体をつなぐのは lead）
- <N> 人が同時に作業するので、動画を撮るときは `--jobs <3>` を付ける（例 `python3 build.py 3 --jobs 3`）。`--stills` と `--kana` は並列数に関係しない
- 同時に実行しても衝突しない：書き込むのは自分の番号のファイル（`scenes/sNN.html`、`seg/aNN.wav`、`seg/vNN*`、`stills/sNN_*`）と、名前にプロセス番号を入れて置き換える一時ファイルだけ。最終の mp4・SRT・`seg/audio.wav` は番号なしの実行のときだけ書く
- 静止画は必ず自分の目で見る。終わりのコマで、要素の重なり、はみ出し、字幕との重なり、文字の小ささを確かめる
- 撮影の目安：動画 1 秒あたり 区間 CPU 約 3 秒。12 並列で 20 秒のシーンが 10〜15 秒で撮れる（ほかの担当と同時に撮ると遅くなる）。録画クリップを含むシーンは、コマごとに seek を待つので遅い

## 3. scene() の引数

```python
from scenes_base import scene, shot, clip, hl, ring, spot, cursor, bubble, card, chip, img, harrow, varrow, asset

scene(tag, title, html, steps, js, en="", hold=None, css="", readings=None)
```

|引数|中身|
|----|----|
|`tag`|右上の札（例「案 A」）。空なら出さない|
|`title`|左上の見出し（短く）。空なら見出しの帯ごと出さない|
|`en`|見出しの横の小さな英字|
|`html`|stage の中身。stage は **1760x796、画面上の位置は (80, 124)**。中の座標は stage の左上が (0, 0)|
|`steps`|読み上げの文の配列。1 文＝ 1 ステップ＝ 1 枚の字幕。字幕は 1 行 50 字まで、長くても 2 行に収める|
|`js`|BUILD 関数の中身（API は references/scene-api.md）|
|`hold`|`{ステップ番号: 追加の秒}`。読み上げの後に見せる間を延ばす|

1 シーンは 1〜5 ステップ。ステップの時刻は読み上げの長さで決まる（頭 0.7 秒、文の間 0.6 秒、終わり 0.9 秒。`video.json` で変えてある場合はそちら）。**シーンの長さはコマ（1/30 秒）の整数倍に丸まる**。

## 4. 画面の決まり

- 1920x1080。左上に見出し、右上に札、下に字幕（白い角丸、下から 44 px、高さ約 72 px）、最下部に進捗の帯（つなぐときに重ねる）
- **stage の外に要素を出さない**。stage の下端（画面の y=920）より下は字幕の領域
- 色は `style.css` の変数を使う。強調はアクセント（`--brand`）と蛍光ペンの黄（`--mark`）。赤・緑は増減の意味があるときだけ
- やらないこと：カードや注釈の片側だけに色の太線を付ける、装飾のためのグラデーション、絵文字、影の重ねすぎ、意味の無い回転
- 文字の大きさ：本文 28 px 以上、補足 24 px 以上、最小 20 px（実画面の中の文字は、寄って読める大きさにしてから強調する）
- <画面に出す固有名・数字・架空の値の決まり（例：SHA やブランチ名は架空のもの。シーン間でそろえる）>

## 5. 録画クリップ

- `clip(id, x, y, w, h, "assets/clips/<name>.mp4", view=None, cls="", url=None, inner="")` で置く。枠は shot と同じ切り抜きなので、`FOCUS` `XY` `CUR` がそのまま効く。座標は**クリップのピクセル**
- 再生は `VID(step, '#id', {d, from, to, rate})`。Before / After を並べるときは、同じ `step` と `d` で 2 つの `VID` を書く
- 操作の時刻と位置は sidecar JSON の `actions`（`clip_actions(name, type)` で読む）。クリップ時刻に印を合わせるには、`AT('#id', 秒)` を `A` `CUR` `CLICK` `FOCUS` の第 1 引数（step）に渡す
- 録画クリップを差し替えたら、そのシーンは自動で撮り直しになる（mp4 と JSON のサイズと更新時刻がハッシュに入る）
- クリップは H.264 の mp4（Chrome が読める形式）。キーフレームは短く（`-g 30` 程度）

## 6. 読み上げ

- 声は `<音声エンジンと話者>`（既定は AivisSpeech の話者 1937616896、`TTS_ENGINE=voicevox` で VOICEVOX。エンジンは止めない）
- 書いたら必ず `--kana` で読みを確かめる。分かっている罠
  - 英字・数字・カタカナの隣の空白は自動で消す。ひらがな・漢字の間の空白は読点になる
  - 「行」は「くだり」になりやすい（表の行なら共通の規則で「ぎょう」）
  - かなで書いた語の「は」は助詞として読まれる。英字の語は readings でカタカナにする
  - <この動画で出てくる固有語の読み（readings.json に登録済みのもの）>
- 字幕の表記と読みは別にできる。字幕は自然な表記で書き、読みは readings で直す

## 7. 仕上がりの確認

- `--stills` の全コマを見て、次を確かめる：stage の外へのはみ出し、字幕との重なり、要素どうしの重なり、蛍光ペンや囲みが狙いの語に乗っているか、寄ったときに文字が読めるか
- `node clipcheck.js . N` で、0.25 秒刻みに、画面外・枠での切れ・文字の重なりを機械的に確かめる（見つかった項目は目で確認する）
- アニメーションは「寄る → 印 → 次へ」のリズム。1 ステップに見せ場を 1〜2 個まで。読み上げが指す物を、その語が読まれる頃に出す（`d` で合わせる）
- 終わったら `python3 build.py N` で動画を撮り、`seg/vNN.mp4` の数コマを ffmpeg で抜いて確かめてから、lead に報告する（パス、秒数、気になる点）

## 8. 既知の注意（共通の部品は変えずに、各シーンで避ける）

- SWAP / SEQ で画像を替えると、替えた画像に z-index が付き、shot の `inner` に置いた `hl` / `ring` / `spot` がその下に隠れる。印を画像より上に出すには、シーンの css で印に z-index を付ける（例 `#s07 #hl1{z-index:5}`）
- 一度 `A(...)` で出し入れした要素に、後からもう一度 `A(..., 'fade')` をかけるときは `{fill:'forwards'}` を付ける。既定の `both` のままだと、後のアニメーションの初期状態（opacity 0）が始まる前から効いてしまい、前の表示を消す
- 同じ要素への `FOCUS` / `CUR` は時刻の順に書く（直前の状態を起点に動くため）
- `--jobs` は argparse で読むので、番号と同じ値でもよい（`python3 build.py 2 3 --jobs 3` は番号 [2, 3]、並列数 3）。`--help` は何も書き込まない
- 字幕が 2 行になる文は、折り返しが語の途中に来ることがある。文の切れ目に `<br>` を入れて改行の位置を決める（読み上げと SRT からはタグを除く）
