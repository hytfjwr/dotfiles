# PR 本文への載せ方

## 置き場所と書き方

動画は本文の上部、概要の直後に置く。
レビュワーが PR を開いて最初に目に入る位置である。
repo の PR テンプレートがあれば、その節の並びを保ったまま、概要の直後に動画の節を足す。

```markdown
## 概要

<変更の要点を 2〜3 文>

## 解説動画

<何の動画か>を約 3 分で説明する（音声あり。<中身の性格>）。

![解説動画](./explainer.mp4)

## <図の見出し>

![<図の要点>](./fig-a.svg)

<図と同じ要点を文でも書く>
```

- 動画の前の 1 行には、長さ、音声の有無、中身の性格を書く。レビュワーはこれを見て、今見るか後で見るかを決める。
  - 図解アニメ：「デモの画面は実装の文言で組んだ再現」
  - 録画：「実画面の録画。Before は main、After はこのブランチ。CPU を 4 倍に絞って同じ操作をした」
- 動画が 2 本あるときは、番号を付けて中身と長さを 1 行ずつ書く（「① 通知がどう変わるか（4 分 24 秒）、② 内部の動き（1 分 50 秒）」）。
- 操作の録画だけを載せるとき（UI の変更のデモ）は、節の見出しを `## 画面` にし、動画の前に操作の流れを 1 文で書く。ライトとダーク、狭い幅のスクリーンショットは表で並べてよい。
- 動画のあとに、図と文で同じ要点を書く。動画を見ない人、音を出せない人にも本文だけで伝わるようにする。
- 字幕ファイル（srt）は本文に載せない。動画に字幕が焼き込まれている。

## 添付

`gh` v2.99 以降の `--attach` を使う（`gh --version` で確かめる）。
動画のあるディレクトリで実行し、本文の `./explainer.mp4` と `--attach` のパスを揃える。

```bash
# 既存の PR の本文を差し替える
gh -R <owner>/<repo> pr edit <n> --body-file body.md --attach ./explainer.mp4 --attach './fig-a.svg#<alt>'

# 新規の Draft PR
gh -R <owner>/<repo> pr create --draft --base <base> --head <branch> --title "<title>" \
  --body-file body.md --attach ./explainer.mp4
```

- 動画には `#alt` を付けない。`cannot set alt text on video` で全体が失敗し、本文も更新されない。画像（svg、png）には `#alt` を付けてよい。
- git repo の外で実行すると `failed to run git` で黙って失敗するので、`-R` を付ける。
- 添付後は必ず本文を確かめる。`./explainer.mp4` が、その場でプレーヤーとして表示される素の URL 行に置き換わることもあれば、URL が本文の末尾に追記されて元の行が壊れたまま残ることもある。

  ```bash
  gh -R <owner>/<repo> pr view <n> --json body -q .body | rg -n 'user-attachments|\]\(\./'
  ```

  末尾に追記されていたら、URL を動画の節へ移して末尾の行を消し、`--attach` なしの `gh pr edit --body-file` で直す。
- 添付できる動画の大きさには上限がある（プランにより 10MB か 100MB）。超えるときは `build.py` の書き出しの crf を上げるか、長さを詰める。
- `Could not resolve to a Repository` が出たら、`gh auth status` で使っているアカウントを確かめて切り替える。

## 差し替え

動画を作り直したら、本文の動画の行を `![解説動画](./explainer.mp4)` に戻した `body.md` で、もう一度 `--attach` する。
古い動画の URL は本文から消える。
差し替えた事実をレビュワーに知らせる必要があれば、PR のコメントに 1 行で書く（「解説動画を、<追加した仕様>を反映した版に差し替えた」）。
