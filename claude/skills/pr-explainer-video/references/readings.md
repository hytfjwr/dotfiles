# 読み上げの罠と確かめ方

TTS は、表記から読みを推測して誤ることがある。
字幕は正しくても、耳で聞くと別の語に聞こえれば、視聴者はそこで止まる。

## 確かめ方

1. `python3 build.py --kana` で、全ステップの読み上げ文と、エンジンが解釈したカナ（アクセント句ごとのモーラ列）を出す。
2. カナを全文読み、次を探す。
   - 英字の綴りの名残、途中で切れた語（「ウォオン / ド」のような）
   - 漢字の誤読（下の表）
   - 助詞が別の語にくっついた読み
3. 書き出した後は、`make_review.sh` の文字起こし（`whisper.txt`）を字幕と突き合わせる。文字起こしの誤りは、聞き取りにくさの目安になる。
4. 直し方は 3 つある。`readings.json`（全シーン共通）か `scene(..., readings=[...])`（そのシーンだけ）で読みを置き換えるか、言い換える。長い語から先に置き換わる。

AivisSpeech は、`audio_query` で返る `kana` を読み上げる文として使う。
そのため、読みの置き換えはそのまま発音に効く。
VOICEVOX ではカナは参考情報で、置き換えは表記の段階で行う。

## 自動で直していること

- 英字、数字、カタカナの隣の空白は消す。英字の後の空白で読みが切れ、「error にし」が「エラー、西」になるためである。
- ひらがなと漢字の間の空白は読点にする。
- 「行」は、前の字が「の」「た」「い」や数字で、後に助詞が続くとき「ぎょう」にする。そのままだと「くだり」と読まれる。

## よくある罠

|表記|誤った読み|直し方|
|---|---|---|
|静的|性的|「静的」を言い換える（「固定の」）|
|試作|施策|「試しに作った」などに言い換える|
|値は|ネワ|`["値は","あたいは"]`|
|章ごと|アキラゴト|`["章ごと","しょうごと"]`|
|近い語|チカイカタリ|言い換える（「似た言葉」）|
|送り手|オクリシュ|`["送り手","おくりて"]`|
|緑か|リョッカ（緑化）|「緑になっているか」に言い換える|
|応答|音（と聞こえる）|「返事」「返ってくる内容」に言い換える|
|この間|このかん|「このあいだ」と書くか言い換える|
|親メッセージ|シンメッセージ|`["親メッセージ","オヤメッセージ"]`|
|i（1 文字の英字）|愛|「「i」マーク」のように名詞を付けて、読みを「アイマーク」にする|
|案E など英字 1 文字の記号|範囲は（アンイーワ）|読みを「イーの案」にする|
|はちにーにー（かなの数字）|「は」が助詞になる|カタカナで「ハチニーニー」と書く|
|status|スタタス|`["status","ステータス"]`|
|SQL、JSON、URL|綴り読みが崩れる|`["SQL","エスキューエル"]` のようにカタカナで登録する|
|429、503 などのコード|「よんひゃくにじゅうきゅう」と数量で読まれる、途中で切れる|1 語のカタカナで登録する（`["429","ヨンニーキュー"]`）|
|一斉に、送出 など|異性に、創出（同音異義語）|言い換える（「同時に」「送り出す」）。読みの置換では直らないことがある|

英字の製品名、コマンド名、設定名は、最初に出たところでカタカナの読みを登録しておく。
同じ語の読みを、シーンごとに変えない。

## 聞きやすさ

- 長い識別子は読み上げず、画面に出す。読みは「通知のチャンネル」「ビルドの記録のテーブル」のように短くする。
- 数字は、単位や助数詞まで読みを決める（「434件」は「よんひゃくさんじゅうよっけん」）。
- 同音異義語が続く文は言い換える。字幕では分かっても、耳では区別できない。
