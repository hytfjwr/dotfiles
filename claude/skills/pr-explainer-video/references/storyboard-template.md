# 絵コンテの雛形

`<workdir>/STORYBOARD.md` にこの形で書く。
シーンの担当者は、この文書と `SCENE_CONTRACT.md` だけを読んで自分のシーンを作れる必要がある。
用語、数字、画面の共通の決まりをここに集め、担当ごとに解釈が分かれないようにする。

````markdown
# 絵コンテ：<動画の題>

<用途（例: Draft PR に添える 3 分の解説動画）>。読み手は <前提知識（例: このサービスのデプロイの流れを知っている開発者）>。
見終わった人が分かること：<1〜3 個>。
内容の正本は <設計書のパス、または PR の番号と diff の範囲>（読むだけ）。数字と用語は正本に合わせる。

## 事実（数字と名前はここに合わせる。変えない）

|項目|値|出典|
|---|---|---|
|<例: タイムアウト>|<例: 900 秒>|<例: config/foo.yml:12>|

## 用語（字幕と画面の表記をそろえる）

- <用語>：<定義>
- 使わない語：<紛らわしい語と、その理由>

## 画面の共通

- 再現する UI（チャット、ターミナル、通知、アプリ画面）の寸法、配色、固定の文言
- 今回の変更点の示し方（例: 蛍光ペンの黄）
- 色の意味（例: 合格は緑、不合格は赤、未実施は灰。それ以外の強調はアクセント色）

## シーン

### s00 タイトル（担当 A）

- tag / title / en：<無しなら「なし」>
- 画面：<何をどこに置くか。ステップごとに何が出るか>
- 読み：
  1. 「<1 文目>」

### s01 <見出し>（担当 B）

- title「<画面上の見出し>」、en `<英語の小見出し>`
- 画面：<step 1 で…、step 2 で…>
- 読み：
  1. 「…」
  2. 「…」

## 全シーン共通の例のデータ

<複数のシーンに同じ具体例（件数、日付、名前）が出るなら、ここに表で一度だけ書く>

## 改訂

- v2：<何をなぜ変えたか>
````

## 書くときの注意

- 1 文は字幕 1 枚に収まる長さ（50 字まで）にする。長い文は分け、読ませる時間が要るなら `hold` を足す。
- 長い識別子（チャンネル名、テーブル名、ARN）は読み上げない。画面に出して、読みは「通知のチャンネル」のように短くする。
- 視聴者の問いの順に並べる。「何が困っていたか → 何を変えたか → どう動くか → 何に気をつけるか」が基本形である。
- 冒頭の 1 文で、動画が何の話かを言い切る。
- 1 分以下の短い動画では、s00 のタイトルだけのシーンを作らず、最初のシーンの見出しと 1 文目で兼ねる。
- 最後のシーンは、レビュワーに見てほしい点や次の手順で締める。まとめの繰り返しにしない。
