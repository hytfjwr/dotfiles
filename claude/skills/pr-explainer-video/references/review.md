# レビューの指示書

書き出した動画は、画面、内容、読みの 3 つの観点で、別々のレビュアーに同時に見せる。
レビュアーは制作の経緯を知らない状態で見るほうが、視聴者と同じ引っかかりに気づける。
モデルは既定か sonnet / opus にし、Fable は使わない。

## 共通で渡すもの

- `<workdir>/reviewN/`（`make_review.sh` の出力）：各ステップの終わりの静止画、シーンごとのコンタクトシート、字幕（srt）、カナ、各シーンの長さ、文字起こし
- `STORYBOARD.md` と、内容の正本（設計書か diff）のパス
- 出力の形：指摘は 1 行 1 件、「シーン番号 / ステップ / 種類 / 何が問題か / 直し方の案」。指摘が無ければ「なし」とだけ書く。好みの話（「もっと派手に」）は書かない。

## 画面のレビュアー

```
あなたは PR の解説動画の画面をレビューする。<workdir>/reviewN/ の静止画とコンタクトシートを Read で見て、次を探す。
- 見切れ：stage や枠の外にはみ出した文字・図形、寄ったときに切れる見出し、画面の外から入ってくる要素
- 重なり：字幕と図、図どうし、印（蛍光ペン、囲み）と本文
- 狙いのずれ：蛍光ペンや囲みが、読み上げの指す語に乗っていない
- 読めなさ：GitHub のプレーヤーで縮めたとき 20px 未満になる文字、背景との差が小さい文字
- 一貫性：同じ意味に違う色、シーン間で同じ物の形や位置が変わる
- 動き：1 ステップに見せ場が多すぎる、印が読み上げより早く・遅く出る、一瞬の白画面やちらつき
- 装飾：グラデーション、影、絵文字、片側だけの色の太線、意味の無い動き
見切れの候補は node <skill-dir>/scripts/clipcheck.js <workdir> の出力と照らす。
```

## 内容のレビュアー

```
あなたは PR の解説動画の台本と画面の内容をレビューする。srt と静止画を読み、内容の正本 <パス> と突き合わせる。
- 事実：数字、名前、順序、条件が正本と一致するか。正本に無いことを言っていないか
- 言い過ぎ：「必ず」「すべて」「常に」など、正本より強い言い方
- 食い違い：シーン間で同じことを違う言い方で言っていないか、前提が途中で変わっていないか
- 抜け：レビュワーが最初に抱く問い（何が変わる、なぜ、どこを見ればよい）に答えているか
- 説明しすぎ：本文やコードを読めば分かる細部に時間を使っていないか
- 用語：STORYBOARD の用語表と、repo の用語の規約に合っているか。造語が無いか
指摘には、正本の該当箇所（パスと行）を添える。
```

## 読みのレビュアー

```
あなたは PR の解説動画の読み上げをレビューする。kana.txt（エンジンが解釈したカナ）と whisper.txt（書き出し後の文字起こし）を、srt（字幕）と突き合わせる。
- 誤読：漢字の読み違い、英字の綴り読み、途中で切れた語
- 聞き違い：文字起こしが別の語になっている箇所（同音異義語、助詞のくっつき）
- 聞きにくさ：長い識別子の読み上げ、数字の読み、1 文の長さ
直し方の案は「readings に [表記, 読み] を足す」か「言い換え：…」の形で書く。
<skill-dir>/references/readings.md の罠の表も参照する。
```

## 指摘を受けたあと

1. 3 人の指摘を、シーンごとにまとめる。同じ箇所への矛盾する指摘は、親が正本に照らして決める。
2. 共通ファイルや `readings.json` の変更は親が行い、シーンの修正は担当（sonnet）に並列で任せる。
3. 修正後は、変えたシーンだけを撮り直して全体を書き出し、次の周のレビュー一式を作る。
4. 2 周で打ち切る。2 周目に残った軽い指摘は、直せるものだけ直して書き出す。
